# 8. 计算机基础知识

## 本章学习目标

学完本章，你应该能完成消防岗位常见的信息输入、文件管理、值班记录和简单表格操作，并知道账号、数据和记录为什么也需要安全管理。

## 一、计算机由什么组成

- **硬件**：可以看到和触摸的设备，如主机、显示器、键盘、鼠标、打印机、硬盘。
- **软件**：运行在硬件上的程序。操作系统负责管理文件和设备，应用软件用于文字、表格、浏览器等具体工作。
- **数据**：报警记录、设备台账、维修记录和检测报告等信息。数据丢失或错误会影响交接班和故障追溯。

## 二、零基础理解：信息是怎样从现场变成可追溯记录的

消防岗位中的计算机不是单纯的办公工具，而是把现场状态转换成可查询、可复核、可交接的信息系统。可以用四个环节理解：

```text
输入：探测器、控制器、操作员录入、检测仪器读数
→ 处理：系统识别地址、分类状态、生成事件和日志
→ 存储：历史记录、值班记录、维修台账、检测报告
→ 输出：屏幕、声光提示、打印、导出、交接报告
```

| 概念 | 零基础理解 | 消防岗位例子 |
| --- | --- | --- |
| 文件 | 保存信息的载体 | 值班记录表、检测报告、设备说明书 |
| 文件夹 | 管理文件的容器 | 按月份或项目保存记录 |
| 数据库 | 按结构保存并检索大量记录的系统 | 控制器历史事件或设备台账 |
| 日志 | 按时间记录系统或操作事件 | 火警、故障、屏蔽、复位和登录记录 |
| 备份 | 在另一位置保留可恢复副本 | 定期备份值班记录和检测资料 |

“复制一份”只是形成副本，不一定等于有效备份；备份还要考虑保存位置、时间、完整性、权限和能否恢复。删除历史记录也不能消除已经发生的火警或故障，只会破坏追溯证据。

### 一个完整例子：从报警到交接

1. 探测器或手动报警按钮产生输入；
2. 控制器识别设备地址并生成火警事件；
3. 图形显示装置、声光设备或打印机输出信息；
4. 操作员核实现场，把时间、地址、现象和处理过程写入值班记录；
5. 维修或检测人员补充原因、措施、复测结果和恢复时间；
6. 交接班人员核对控制器当前状态、未闭环事项和纸面/电子记录。

如果屏幕显示、历史日志和现场现象不一致，应保留差异并分别核查，不能直接删除或修改原始记录来“统一口径”。

## 二、文件管理练习

用一个练习文件夹模拟值班资料：

1. 新建“值班记录”文件夹；
2. 建立按日期命名的记录文件；
3. 复制一份作为备份，不直接覆盖原始记录；
4. 使用清晰的名称区分“原始记录、复核记录、整改记录”；
5. 不随意删除或修改已经提交的记录。

复制、移动、重命名和删除的区别要理解：复制产生副本，移动改变位置，重命名改变标识，删除可能使记录无法追溯。

## 三、值班记录和表格

电子表格由工作簿、工作表、行、列和单元格组成。可以用表格记录时间、设备编号、状态、异常、处理人和复核人。

- `SUM` 用于合计；
- `AVERAGE` 用于平均值；
- 排序和筛选用于查找某个设备、某一天或某种异常；
- 输入日期、设备编号和状态时要保持格式一致，避免同一设备出现多个写法。

练习：建立 5 条虚拟报警记录，按设备编号筛选，再统计某一类报警数量。重点不是背快捷键，而是能让别人读懂并复核你的记录。

## 四、账号和信息安全

消防控制室或考试系统可能使用个人账号。不要把账号密码写在公开位置、借给他人登录或在不明设备保存密码。记录中也可能包含建筑布局、设备地址和故障信息，应按单位制度管理。

## 五、消防控制室信息系统的常见操作边界

图形显示装置、值班电脑、打印机和控制器之间的显示内容可能因系统品牌和配置不同而不同，但学习时要抓住不变的判断逻辑：

1. 先确认事件类型、时间、设备地址或区域；
2. 再查看相关历史记录、联动状态和反馈信息；
3. 需要打印或导出时，保留原始记录并注明导出时间；
4. 发现显示与现场不一致时，记录差异，不用截图或删除记录“修正”事实；
5. 网络、打印或图形显示故障不能直接推断现场消防设施失效，应分别核查主机、通信、显示终端和现场设备。

> [!WARNING]
> 不要把电脑显示“正常”当作现场设备一定正常，也不要为了消除故障提示而删除历史记录、重装系统或擅自修改权限。
